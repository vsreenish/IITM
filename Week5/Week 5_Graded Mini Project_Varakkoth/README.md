# MP1 · Prompt Lab — Compare LLM Strategies on a Task

**Sreenish Varakkoth · Week 5 Graded Mini Project**

Compares four prompting strategies on one structured-extraction task: pull
`company`, `role` and `years_experience_required` out of a job-posting snippet.
Ten snippets × four strategies = 40 `gpt-4o-mini` calls, scored against a golden
set three ways, with cost and latency captured per call.

## Running it

The provided datasets are not bundled here. Put the course-supplied
`job_snippets.jsonl` and `golden_set.jsonl` in a `data/` folder beside the
notebook:

```
mp1_prompt_lab.ipynb
data/job_snippets.jsonl
data/golden_set.jsonl
```

The notebook also falls back to `../data`, so it runs unmodified from the
original course package layout (`MP1_PromptLab/learner/`) with no edits.

```bash
pip install -r requirements.txt
export OPENAI_API_KEY=sk-...        # Windows PowerShell: $env:OPENAI_API_KEY = "sk-..."
jupyter notebook mp1_prompt_lab.ipynb
```

Then **Run All**, top to bottom. The notebook is ordered so each step depends
only on the ones above it.

- **Runtime:** roughly 30 seconds. The 40 worker calls run concurrently
  (`asyncio.gather`, capped at 8 in flight by a semaphore), as do the 40 judge calls.
- **Cost:** about **$0.026** per full run — $0.0028 for the `gpt-4o-mini` worker
  calls and $0.0236 for the `gpt-4o` judge calls.
- **Outputs written:** `mp1_comparison.md` (a submitted deliverable, regenerated
  on every run) and `results.json` (the raw scored rows, kept so the analysis can
  be redone without spending another 80 API calls). Both are written into the
  notebook's own folder.

## How the pipeline fits together

1. **Load** — 10 snippets plus the golden set, keyed by `id` for O(1) lookup during scoring.
2. **Four strategies** — each is a function `snippet_text -> messages`, so they are
   interchangeable and share one `TASK_INSTRUCTION` constant. Keeping the instruction
   identical across strategies means the *only* variable is the prompting technique.
3. **Async batching** — one `call_llm` helper wraps every API call with bounded
   concurrency, retry-with-backoff on transient errors, and per-call token/cost/latency
   capture. Both the worker and the judge go through it.
4. **Scoring** — three signals per row: exact-match accuracy (0–3), parse success,
   and a `gpt-4o` rubric score (1–4).
5. **Analysis** — headline table, per-field breakdown, the j10 null trap, judge-vs-exact-match
   disagreements, and a strict-vs-lenient comparison that separates model error from
   measurement error.

## Interpreting the results

**Read the tables in this order.**

**1. Headline metrics.** Sorted best-to-worst on accuracy. `few_shot` leads at
2.8/3; the other three tie at 2.7/3. Parse rate is 1.00 everywhere. Cost is in
cents for the whole 10-snippet batch.

**2. Per-field accuracy.** This is where the headline number becomes legible. `role`
is 1.00 for every strategy and `company` is 0.80 for every strategy — so neither
field distinguishes the strategies at all. The entire difference lives in
`years_experience_required`.

**3. Strict vs lenient accuracy.** Lenient scoring ignores trailing punctuation.
Every strategy gains exactly 0.2, which quantifies how much of the apparent error
is a *scoring artifact* rather than a model mistake. `few_shot` reaches a perfect
3.0/3 under lenient scoring.

**4. The failure cells.** Two distinct patterns, and they are the interesting part:

- **j02 and j08 — punctuation.** The model returns `"Northwind Ltd."` where gold
  says `"Northwind Ltd"`. The snippet reads *"…at Northwind Ltd. Reporting to…"*,
  so the period is a sentence terminator that is genuinely ambiguous with an
  abbreviation full-stop. This costs 8 of 40 rows under strict matching and is
  the source of every judge disagreement — the judge scored all 8 as 4/4, correctly.
- **j05 — the `0` vs `null` boundary.** Gold is `0` ("fresh grads welcome — no
  prior experience required"). Zero-shot, structured and chain-of-thought all
  returned `null`; only few-shot returned `0`. This single snippet is the *only*
  genuine model error in the run, and the only reason the strategies differ.

**5. j10, the null trap.** All four strategies returned `null` correctly —
fabrication rate 0.00 across the board. See the write-up for why that trap failed
to catch anything here.

**A caution on the numbers.** Ten snippets means one snippet is worth 0.1 of a
per-field score, so the accuracy gaps in these tables rest on single rows. The
conclusions are stated as directional, not statistically significant. Latency is
measured inside the concurrency semaphore, so it excludes queue wait but still
includes connection setup on the first calls.

## Findings and recommendation

Full reasoning is in [`mp1_writeup.md`](mp1_writeup.md). In short: **few-shot wins**
— highest accuracy, top judge score, fastest median latency, and negligible cost.
Chain-of-thought cost 3.4× more than zero-shot and was 3× slower for no accuracy
gain at all, because this extraction task has no reasoning depth for it to exploit.
